# 🌾 DalaScan AI

**Диагностика заболеваний пшеницы по фотографии** — MVP для хакатона на Python 3.11 и Streamlit. Бесплатный локальный инференс без внешних API и ключей.

> Для настоящего режима нужны веса `model/wheat_model.pth` и локальная проверка снимков CLIP. Если весов болезней нет, включается **демонстрация интерфейса, а не диагностика**. Перед практическим использованием необходима независимая проверка качества на ваших полях.

## Возможностии

- Загрузка JPG/JPEG, PNG, WEBP и съёмка камерой браузера.
- Проверка содержимого, целостности, EXIF-ориентации, лимитов 15 МБ / 25 Мп; RGB и уменьшение до 1280 px.
- Неблокирующие рекомендации по яркости, резкости и разрешению.
- Четыре состояния: здоровая пшеница, бурая ржавчина, жёлтая ржавчина, септориоз.
- Top-3 с полосами вероятностей, справочный риск, признаки и безопасные действия.
- Пороговая интерпретация: ≥70% — вероятное состояние; ≥45% и <70% — дополнительный снимок; <45% — состояние не определено. Пороги применяются до округления.
- Пять последних анализов в памяти текущей сессии и очистка истории.
- Светлая адаптивная тема, локальная модель CPU/CUDA и кэш загрузки весов.

## Скриншот

**Место для скриншота:** запустите приложение, загрузите свой снимок и добавьте изображение интерфейса здесь. Не используйте демонстрационный результат как доказательство качества распознавания.

## Быстрый запуск в Windows

Установите **64-битный Python 3.11** с [python.org](https://www.python.org/downloads/). При установке включите `Add python.exe to PATH`. Проверьте `python --version`, затем откройте PowerShell в папке `dalascan-ai`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

После установки зависимостей приложение запускается **одной командой** `streamlit run app.py`. Откройте [localhost:8501](http://localhost:8501). Для остановки нажмите Ctrl+C в терминале.

Если PowerShell блокирует активацию окружения, изменение политики не обязательно. Используйте команды ниже после успешного создания `.venv`. Если папки `.venv` нет, сначала проверьте установку Python и выполните `python -m venv .venv`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Установка требует интернета. После установки демонстрация и инференс работают без доступа к сети. Для CUDA нужна совместимая сборка PyTorch: используйте [официальный установщик PyTorch](https://pytorch.org/get-started/locally/) для своей ОС и видеокарты, сохраняя пару версий torch 2.7.1 / torchvision 0.22.1. CUDA выбирается автоматически при `torch.cuda.is_available()`.

## Проверка снимков перед диагнозом

В настоящем режиме перед моделью болезней запускается отдельный локальный CLIP ViT-B/32.
Он сравнивает фото с фиксированными описаниями пшеницы, других растений и посторонних объектов.
Это **экспериментальная zero-shot проверка**, а не обученная и проверенная на полях система определения вида растения.
Она может принять ячмень, рис или другой похожий злак за пшеницу и может попросить переснять настоящий лист пшеницы.

- **Похож на пшеницу**: выполняется классификация заболевания.
- **Вероятно, не пшеница**: диагноз не выдаётся.
- **Не удалось подтвердить**: диагноз не выдаётся, приложение просит переснять лист.
- **Проверка недоступна или сломалась**: настоящая диагностика блокируется; скрытого обхода нет.
- **Демонстрационный режим**: проверка пропускается с явным предупреждением, результат остаётся симуляцией.

Установка на новой машине после создания и активации окружения:

```powershell
python -m pip install -r requirements.txt
python scripts/download_guard.py
python -m streamlit run app.py
```

Однократно скачивается примерно **605 МБ** бесплатных весов из `openai/clip-vit-base-patch32`.
API-ключ не нужен. Зафиксирована версия `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`.
После загрузки инференс работает без сети, с `local_files_only=True`; снимки никуда не передаются.
В этой рабочей папке веса проверки уже скачаны.

Каталог `model/image_guard/` исключён из Git, ZIP исходников и Docker build context.
В Docker подключайте всю папку `model` через существующую команду `--mount`.
Память и время первого запуска возрастают из-за отдельной модели; обе модели прогреваются заранее.
Время пользовательского анализа теперь включает также проверку CLIP.

Пороги, источники и ограничения описаны в [model/IMAGE_GUARD.md](model/IMAGE_GUARD.md).

## PDF-отчёт обследования

После анализа раскройте «Скачать отчёт обследования», укажите поле/участок и при необходимости заметку,
затем нажмите **«Скачать PDF»**. Язык отчёта соответствует переключателю Русский / Қазақша.

Отчёт содержит фотографию именно выполненного анализа, дату с часовым поясом, время обработки,
результат проверки снимка, Top-3 и рекомендации (если диагностика состоялась), предупреждения
о качестве и ограничениях. Для отклонённых снимков отчёт прямо сообщает, что диагноз не выполнялся.
При низкой уверенности сохраняется отказ от надёжного диагноза. Демо-отчёты помечены на каждой странице.

PDF создаётся в памяти, без отправки снимков и внешних API. Фотография текущего результата хранится
только в памяти сессии; пять записей истории не содержат фотографии. В отчёт встроен свободный
DejaVu Sans с поддержкой русских и казахских букв; лицензия находится в `assets/fonts/`.
Заметки пользователя экранируются и не интерпретируются как HTML.

## Демонстрационный режим

Включается по умолчанию при отсутствии весов болезней и заметно обозначен в интерфейсе и истории. Вероятности вычисляются из SHA-256 RGB-пикселей подготовленного снимка и его размеров. Для одинакового изображения результат воспроизводим; вероятности всех четырёх классов суммируются до 1. Это не результат нейросети и не оценка состояния растения. Перекодирование, изменение ориентации или размера могут изменить пиксели и результат.

Режим полезен для проверки загрузки, результатов, порогов и истории до обучения. Нет автоматического скрытого перехода с настоящей модели на demo: если весов нет или они повреждены, приложение объясняет проблему, а режим выбирает пользователь.

## Подключение настоящей модели

1. Обучите MobileNetV3 Small по инструкции ниже.
2. Разместите доверенный файл в `model/wheat_model.pth`.
3. Отключите «Демонстрационный режим» в боковой панели.

Поддерживаются обычный `state_dict` и checkpoint с ключом `model_state_dict`. Выходной слой — `Linear(..., 4)`. Порядок выходов **healthy, leaf_rust, septoria, yellow_rust**: это алфавитный порядок `ImageFolder`, а не порядок перечисления болезней в тексте задания. Скрипт обучения проверяет этот контракт у всех трёх выборок. Checkpoint с несовпадающим `classes` отклоняется; порядок голого state_dict невозможно проверить по метаданным, поэтому за него отвечает автор весов.

В инференсе и val/test используются одни и те же Resize(256), CenterCrop(224), ToTensor, ImageNet mean/std из `utils/model_config.py`. Модель использует `eval()`, `no_grad()` и softmax. Архитектура при инференсе создаётся с `weights=None`, поэтому никаких скачиваний нет. Кэш учитывает размер и время изменения файла. Загрузка использует `weights_only=True`; выбирайте только доверенные файлы.

## Датасет и обучение

Подготовьте настоящие фотографии с проверенными агрономом метками и правом использования. Для каждого класса нужна достаточная представленность условий освещения, сортов и стадий заболевания. Не разделяйте фотографии одного растения или серии между выборками: это создаёт утечку данных. Test отложите до окончательной оценки. Удалите дубликаты и повреждённые файлы.

```text
dataset/
├── train/
│   ├── healthy/
│   ├── leaf_rust/
│   ├── yellow_rust/
│   └── septoria/
├── val/
│   ├── healthy/
│   ├── leaf_rust/
│   ├── yellow_rust/
│   └── septoria/
└── test/
    ├── healthy/
    ├── leaf_rust/
    ├── yellow_rust/
    └── septoria/
```

Все 12 папок должны содержать изображения. Пример начального разделения: 70/15/15 по независимым растениям или участкам с сохранением классов. Данные пользователей и датасет не включаются в Git.

```powershell
python scripts/train_model.py --data dataset --epochs 15 --batch-size 16 --lr 0.001 --patience 4 --seed 42 --output model/wheat_model.pth
```

Первый запуск бесплатно скачивает предобученные веса **ImageNet** через torchvision; нужен интернет, но не API-ключ. Эти веса сами по себе не распознают четыре болезни пшеницы. Для офлайн-обучения заранее заполните стандартный кэш torch на той же машине.

Только train получает RandomResizedCrop, отражение, небольшой поворот и изменение яркости/контраста. Val/test стабильны. Обучение использует Adam и cross entropy, выводит loss/accuracy по эпохам, сохраняет лучшую validation accuracy и делает early stopping (по умолчанию 4 эпохи без улучшений). После обучения на test оценивается **лучшая** модель. Batch size минимум 2; `num_workers=0` упрощает запуск в Windows.

Checkpoint содержит веса, классы, лучшую val accuracy, эпоху, параметры обучения, архитектуру и итоговые test loss/accuracy. Фиксированный seed улучшает воспроизводимость, но идентичность между разными GPU/версиями библиотек не гарантируется. При нехватке памяти уменьшите batch size. Обучение на CPU может занять значительно больше четырёх дней при большом датасете — заранее ограничьте размер эксперимента.

```powershell

```

Тесты проверяют справочник, неизвестный класс, пороги, детерминизм demo, сумму вероятностей, RGB/RGBA, форматы, EXIF, повреждённые файлы, лимиты, качество, оба формата весов, порядок классов, запуск UI и очистку истории. Временные случайные веса создаются pytest исключительно для проверки загрузчика и не сохраняются в `model/`. Проверки не измеряют агрономическую точность модели.

## Скорость, конфиденциальность и ограничения

- Цель — менее 5 секунд на один анализ после прогрева модели. Время измеряется `perf_counter`: проверка и декодирование файла, подготовка, качество, инференс. Загрузка файла через сеть, отрисовка и первичная загрузка/прогрев весов в него не входят. При превышении 5 секунд UI показывает предупреждение; на любом оборудовании SLA не гарантируется.
- Снимки обрабатываются в памяти сервера; приложение не пишет их на диск и не вызывает внешние API. При локальном запуске сервер — ваш компьютер. На удалённом сервере изображения передаются этому серверу, поэтому публиковать приложение следует только в доверенной среде с HTTPS.
- История привязана к Streamlit-сессии, без БД и общего журнала. Перезапуск/потеря сессии удаляют её; очистка истории не убирает текущий результат.
- Камера зависит от разрешений браузера и безопасного контекста (HTTPS/localhost).
- Добавлена экспериментальная CLIP-проверка «похоже на пшеницу». Неподходящие и сомнительные снимки не поступают в модель болезней. Это не ботанически валидированный классификатор: похожие злаки могут пройти фильтр. Сегментации листа, оценки тяжести по площади и распознавания неизвестных болезней нет.
- Softmax не является калиброванной достоверностью; пороги 45/70% — правила интерфейса, а не доказанные клинические/агрономические пороги. Даже высокая вероятность не гарантирует правильный результат.
- Риск в справочнике — общая характеристика состояния. При недостаточной уверенности риск снимка отмечается как неопределённый. Справочные признаки не являются обнаруженными моделью признаками.
- Оценка резкости/яркости — эвристика; однотонный здоровый лист может получить совет переснять фото.
- Нет авторизации, ограничения частоты запросов и инфраструктуры для массового публичного сервиса. MVP рассчитан на демонстрацию и локальную проверку.

**Результат является предварительной оценкой и не заменяет консультацию агронома. Перед применением средств защиты растений необходимо проверить местные регламенты и инструкцию производителя.**

## Демонстрация для жюри (2 минуты)

1. Представьте задачу: быстро начать обследование пшеницы по фото листа.
2. Покажите выбранный режим. Если весов нет, прямо скажите: «Это демонстрация интерфейса, не обученная диагностика».
3. Загрузите собственную фотографию, нажмите «Провести диагностику».
4. Покажите время, Top-3, пороги уверенности и рекомендации по съёмке.
5. Откройте историю и очистите её. Переключите реальный режим без весов, чтобы показать понятную обработку ошибки.
6. Расскажите о следующем шаге: размеченный датасет, обучение и проверка с агрономом. Не заявляйте точность до измерений.
